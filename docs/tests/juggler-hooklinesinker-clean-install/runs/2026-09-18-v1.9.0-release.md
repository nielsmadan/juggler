## Restart failure

The authenticated original Claude process had two running ledger records for the same prefixed
iTerm2 session ID, PID and process start time, but different Claude session IDs. These records
were already present when testing resumed after login; this run did not establish which exact
login action created the older record.

| Record | Event | Phase | Last observation (UTC) |
|---|---|---|---|
| Current Claude thread | `PermissionRequest` | `permission` | `2026-09-18T12:43:56Z` |
| Older thread, same terminal/process | `SessionStart` | `idle` | `2026-09-18T12:18:27Z` |

The ledger returned the current record before the older one. Before quitting Juggler, its row
correctly read `permission`. After relaunch, there were still exactly two terminal rows, but the
original row read `idle`. Claude still displayed `This command requires approval`, and the ledger
still contained the current `PermissionRequest` record. A second restart reproduced the same result.
Approving the pending command produced fresh events and corrected the row.

The source inspection supports a likely cause: `HookServer.hydrate` replays every running binding
in returned order, while `handleStatus` updates rows by terminal identity. There is no newest-record
selection between different bindings for the same terminal in that path. This is a diagnosis,
not a separately instrumented observation of the in-memory update sequence.

To repeat the failure, first establish the same ledger precondition: two running records with
different Claude session IDs for one terminal/process, with an older idle record returned after
the current record. Then:

1. In manual permission mode, ask Claude to run `python3 -c 'print("vm-ui-permission-ok")'`.
2. Leave its approval prompt pending; confirm both the ledger and Juggler show permission.
3. Quit and reopen Juggler without sending another Claude message.
4. Compare the visible row against the pending prompt and both ledger records.

Expected: the newer record wins and the row remains permission. Actual: the row becomes idle.
As a control, a fresh session with only one ledger record retained its pending permission state
across restart. The observed failure is therefore specific to competing records, rather than
permission hydration failing for every session.
